# 06: 服务号自定义菜单

**What to build:** 运营在服务号上编辑并保存自定义菜单，保存本身不调用微信。发布时，系统用这份已保存的菜单整份替换该服务号在微信上的默认菜单。订阅号、小程序，以及没有拿到菜单能力的平台授权，会在本地被拒绝。

**Blocked by:** 05 — 微信应用连通性测试与失效

**Status:** ready-for-agent

- [ ] 运营可以在服务号上编辑自定义菜单并保存在本系统，保存不调用微信
- [ ] 叶子按钮可以打开网页，或跳转到一个小程序；父按钮只用来容纳子按钮
- [ ] 本地保存的菜单可以包含子按钮，不受原型里三个一级按钮的限制
- [ ] 发布把当前已保存的整份菜单交给微信，替换该服务号的默认菜单
- [ ] 发布被微信拒绝或超时时，应用不失效，上次被微信接受的菜单仍是已发布的那一份
- [ ] 订阅号和小程序在本地拒绝菜单，不调用微信，应用不失效
- [ ] 平台授权没有授予菜单能力时，在本地拒绝，不调用微信，应用不失效
- [ ] 应用已停用、已失效、已撤回，或它挂着的平台未就绪时，发布被拒绝；已撤回的应用也不能再编辑菜单
- [ ] 菜单的编辑和发布做在微信应用的详情里，使用已有的 `wechat:app:update`
- [ ] 上述行为由微信领域服务测试覆盖；发布的成功、拒绝和超时来自可脚本的开放接口端口
