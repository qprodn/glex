# 02: 平台验证票据与平台连通性测试

**What to build:** 每条微信平台有自己的回调地址。它收到自己的加密验证票据之后变为就绪；票据丢失只让这条平台未就绪。运营可以对就绪的平台做连通性测试。全网发布的测试报文会得到应答，并且不产生微信应用或微信下发。

**Blocked by:** 01 — 登记微信平台

**Status:** ready-for-agent

- [ ] 每条平台向运营展示自己的回调地址
- [ ] 一条平台收到加密验证票据后变为就绪，其他平台不变
- [ ] 同一条平台后续收到的验证票据替换它当前持有的票据
- [ ] 验证票据丢失后，这条平台变为未就绪，不产生微信应用，也不把任何微信应用标为失效
- [ ] 就绪的平台可以做微信连通性测试；成功不改变任何微信应用
- [ ] 凭证不齐或还没有验证票据时，平台连通性测试失败，不改变任何微信应用
- [ ] 打到这条平台回调上的全网发布测试报文被应答，不创建微信应用，也不创建微信下发
- [ ] 明文推送、兼容模式推送，以及验签失败的推送被拒绝，不改变平台或应用
- [ ] 后台可以发起平台连通性测试。权限是 `wechat:platform:probe`
- [ ] 领域服务测试用可脚本的开放接口端口表示测试成功或失败；推送验签使用真实协作对象，覆盖明文、兼容模式和坏签名
