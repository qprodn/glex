# 10: 网页授权与交接短码

**What to build:** 运营给服务号配好返回地址，并选择网页授权只取 openid，或同时要昵称和头像。用户在微信完成授权后，浏览器只回到这条应用上保存的返回地址，并带上一个一次性交接短码。调用方用短码换回这次身份，短码用过即废。

**Blocked by:** 05 — 微信应用连通性测试与失效

**Status:** ready-for-agent

- [ ] 服务号的网页授权默认只取 openid，运营可以改成同时要昵称和头像
- [ ] 运营可以把返回地址保存在这条服务号上
- [ ] 没有返回地址时，网页授权不能开始
- [ ] 订阅号、小程序、没有网页授权能力的平台授权、已停用、已失效、已撤回，或所挂平台未就绪时，网页授权不能开始
- [ ] 微信接受授权后，浏览器只跳到这条应用上已经保存的返回地址；请求里不能另指一个地址
- [ ] 跳转带回的是一次性交接短码
- [ ] 短码可以兑换一次，得到 openid 和 unionid；只有这条应用要求了昵称和头像时，结果里才带这两项
- [ ] 同一个短码再次兑换，或兑换一个本系统没发过的短码，都会失败
- [ ] 兑换不创建微信用户、系统用户或登录会话，也不写登录日志
- [ ] 开始网页授权和兑换短码都不要求后台的登录态
- [ ] 本票不规定交接短码的有效时长
- [ ] 返回地址和授权范围的设置做在服务号详情里，使用已有的 `wechat:app:update`
- [ ] 领域服务测试覆盖不能开始、一次性兑换、重复兑换，以及只在要求了资料时才返回昵称和头像
