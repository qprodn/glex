# 07 — 退款链路：多次部分退款与上限

**What to build:** 对 PAID 的 Payment 发起 Refund：按支付单维度的防重锁内校验「已退 + 本次 ≤ 已付」；退款状态机 PENDING → SUCCESS / FAILED（CAS）；微信退款回调与 QueryRefund 推进、支付宝当面付同步退款结果立即结算。退款不改变支付单状态，只累加已退金额——「钱到过账」与「钱退回去」是两个独立事实。细节参见 `.scratch/payment/design.md` §5、§7。

**Blocked by:** 06 — 回调链路：免鉴权路由、回调流水、方言 ACK。

**Status:** ready-for-agent

- [ ] 一笔支付多次部分退款全部成功，支付单已退金额正确累计
- [ ] 超出累计上限的退款被业务错误拒绝（Warn 级面包屑，非 Error）
- [ ] 全额退完后支付单仍为 PAID 且已退金额等于支付金额
- [ ] 微信退款回调驱动状态推进；支付宝同步退款在创建后立即结算
- [ ] 并发两笔退款竞争同一上限时恰好一笔成功的测试
