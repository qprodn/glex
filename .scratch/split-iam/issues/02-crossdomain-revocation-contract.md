# 02 — Prefactor: stand up the Coze-style crossdomain revocation contract

**What to build:** Create `internal/crossdomain/authn` in the anti-corruption
shape recorded in ADR 0017: `contract.go` with the consumer-shaped
SessionRevoker interface, a `model/` package holding the flat revocation
request snapshot (affected System Users, optionally the Login Session to
preserve), an `impl/` package whose adapter wraps the login-session capability
to satisfy the contract, and a mockgen-generated mock package. The four
revocation-consuming usecases switch to the constructor-injected contract.
Security-change classification stays pure domain logic; caller usecases
assemble the request. This lands green on main and validates the layer's shape
before any physical move.

**Blocked by:** None — can start immediately (independent of 01).

**Status:** done

- [x] `internal/crossdomain/authn` has contract.go, model/, impl/, and a generated mock subpackage
- [x] The adapter lives in the crossdomain impl package, wrapping the provider capability; infra no longer owns the revoker narrowing
- [x] All revocation-consuming usecases receive the contract by constructor injection; the old domain-owned port is gone
- [x] No domain package imports crossdomain; the contract exposes only model/ snapshots, never provider domain types
- [x] `make all` green; security-change integration tests stay green with unchanged revocation behavior

## Comments

Implemented as a zero-behavior-change prefactor on top of 01:

- `internal/crossdomain/authn` in the ADR 0017 shape: `contract.go`
  (`SessionRevoker` with the single `RevokeSystemUsers(ctx, *model.RevocationRequest)`
  method), `model/` holding the flat request snapshot (affected System User
  IDs + one optional preserved Session ID), `impl/` whose
  `NewSessionRevoker` wraps `domain/iam.LoginSessionRepo` (the narrowing
  moved out of infra; `internal/infra/iam/session_revoker.go` deleted), and
  `authnmock/` generated by mockgen via a `go:generate` directive.
  mockgen is pinned as a Go tool dependency (`tool go.uber.org/mock/mockgen`),
  so `make generate` reproduces the mock and `go mod tidy` keeps it.
- The four revocation-consuming usecases (User, Role, Menu, and Auth's
  UpdateUserRoles — previously passing its whole sessionRepo as the revoker)
  now take `authn.SessionRevoker` by constructor injection. The shared helper
  in `application/iam/security_change.go` still classifies with the pure
  domain policy types and assembles the flat model request (dedupe/sort/last
  policy wins preserved; a preserved session only ever targets the single
  user of a self password change, so the fold is behavior-identical).
- Domain `SessionRevoker` interface deleted from `login_session.go`;
  `LoginSessionRepo.RevokeSystemUsers` and the security-change integration
  tests are untouched. `TestSecurityChangeCommitFailureKeepsSessionsRevokedIntegration`
  (miniredis + sqlmock) passes end-to-end through the new adapter; the
  PostgreSQL/Redis-gated integration tests compile and skip exactly as
  before (no local stores in this environment).
- New `internal/crossdomain_contract_test.go` pins the layer invariants:
  domain never imports crossdomain, crossdomain outside impl/ never imports
  a provider domain, application never imports a crossdomain impl adapter
  (negative-probed before trusting it).

Code-review follow-ups: the request assembly now rejects a batch that
classifies two distinct preserved sessions instead of silently picking one in
random map order (deterministic fold over sorted ids plus an explicit error,
covered by `security_change_test.go`), and AGENTS.md's cross-domain section
and layer table were synced to ADR 0017 (crossdomain tree entry, layer row,
every-call-goes-through-the-layer rule, sanctioned `model/` naming exception).
