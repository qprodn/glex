# 重构：按 coze 方式重组 application 与 domain

## 目标形态（已确认的决策）

1. **删掉独立 Usecase 层**：每个 `*Application` 结构体直接持有 domain 端口、`Transaction`、crossdomain 契约，RPC 方法体内完成 DTO↔DO 转换 + **跨领域编排**（事务包裹、crossdomain 调用、补偿）。
2. **领域内编排下沉**：唯一性检查、可分配性校验、树组装/路由选择等**领域内逻辑**移入 `domain/<模块>/service`，以接收端口参数的无状态函数形式存在（不动 Wire）。
3. **domain 按 `entity / repository / service` 子包拆分**（coze 式），删除 AGENTS.md 的禁止条款。
4. 保留 Wire 构造函数注入、保留 `UserApplication`/`NewUserApplication` 命名、crossdomain（ADR 0017）不动。行为完全不变，纯结构重排。

## 一、domain 拆分映射

三个模块统一规则：**根包只留 `errors.go`**（所有 `Err*` 保持 `domain/user.ErrXxx` 引用形态，改动最小，子包引用它不构成环）；**entity** = DO/值对象及其上的方法；**repository** = 端口接口 + 端口的请求/响应形状 + `ListOption` 族；**service** = 领域内编排与纯规则函数（需要读库的以端口为参数）。

### domain/user
- 根 `errors.go`：全部 6 个 `Err*`。
- `entity/user.go`：`User`（含 `SessionRevocationFrom`）、`CurrentUserInfo`、`SessionRevocation` + 两个策略构造器 + `SystemUserSessionRevocation`。
- `repository/user.go`：`UserRepo`、`UserUpdate`、`ListOption` 族（list_option.go 移入）。
- `service/user.go`：`AssertUnique(ctx, UserRepo, *User, excludeID) error`（原 usecase 私有 `assertUnique`）。

### domain/access
- 根 `errors.go`：全部 14 个 `Err*`（含 access 自有的 `ErrUserNotFound`）。
- `entity/`：`menu.go`（`MenuType*` 常量、`Menu` + `Validate`/`AuthorizationChangedFrom`）、`role.go`（`Role` + 两个方法）、`authorization.go`（`SuperadminRoleKey`）。
- `repository/`：`menu.go`（`MenuRepo`、`MenuUpdate`、`MenuRouteAccess`）、`role.go`（`RoleRepo`、`RoleUpdate`、`RoleMenuLink`）、`user_role.go`（`UserRoleRepo`、`RoleAssignment`、`RoleUser`）、`authorization.go`（`AuthorizationResolver`、`AuthorizationResolution`）。
- `service/`：`menu.go`（`ValidateMenuType`、`AssertSiblingNameUnique`、`BuildMenuTree`、`SelectUserRouteTree`——后两个用 application 里的真实实现替换 domain 里那三个**死代码**版本后删除死代码；`CheckedMenuIDs` 同理从 usecase 实现移入，`dedupeIDs`、`hasExactRoleKey` 成为 service 未导出助手）；`role.go`（`Validate`、`AssertRoleUnique`、`AssertMenusGrantable`、`AssertRoleDisableAllowed`）；`role_assignment.go`（`AssertUserExists`、`AssertRolesAssignable`）。

### domain/authn
- 根 `errors.go`：全部 15 个 `Err*` + `NewLoginLocked`。
- `entity/`：`principal.go`（`Principal`、`NewPrincipal`、`HasPermission`/`HasRole`、`superadminPermission`）、`login_session.go`（`LoginSession`、`AuthorizationSnapshot`、`LoginResult`）、`auth_login.go`（`LoginAccount`）。
- `repository/`：`auth_login.go`（`LoginAccountReader`/`LoginAccountStore`/`CredentialIssuer`/`AuthLoginBackend`）、`credential.go`（`CredentialRepo`）、`login_session.go`（`LoginSessionRepo`、`LoginCounterRepo`、`ListOption` 族）、`authenticator.go`（`Authenticator`）。
- `service/`：`credential.go`（`HashPassword`、`VerifyPassword`、`DecoyCredentialHash`）、`principal.go`（`WithPrincipal`/`PrincipalFromContext`，保持对 `pkg/middleware/auth` 的既有委托）、`login.go`（原 usecase 私有的登录失败归一化 `invalidLogin` → 接收 `LoginCounterRepo` 参数的导出函数）。

同步：重写 `internal/domain/user/README.md`（现内容明确禁止此结构）；更新所有引用方 import（application 3 模块、infra 3 模块、crossdomain 2 个 impl、server、各测试）。

## 二、application 合并（每模块）

**user**：`UserApplication` 字段改为 `repo`、`credentials`（crossdomain）、`tx`、`revoker`、`logger`；构造器 `NewUserApplication(repo, credentials, tx, revoker, logger)`。RPC 方法内联原 usecase 流程（如 `CreateUser`：密码检查 → `service.AssertUnique` → `tx.InTx{建用户 + 写凭证}`）。删除 `user_usecase.go`、局部 `userUsecase` 接口、未导出构造器；`security_change.go`（跨域吊销协调）留在 application；`transaction.go` 保留（三份同型接口维持现状，不合并——合并进根包会与 ProviderSet 成环）。

**access**：`menu.go`、`role.go`、`role_assignment.go` 各自吸收对应 `*_usecase.go`；领域内校验改为调 `accessservice.*`，`buildTree`/路由选择/`CheckedMenuIDs` 改调 service；`GetRouters` 的路由渲染助手原样留在 menu.go。`security_change.go` 留在 application。删除三个 `*_usecase.go`。

**authn**：`login.go` 吸收 `login_usecase.go`（字段 `login`、`counterRepo`、`sessionRepo`、`authorizer`、`tx`、`logger`、可测试的 `now`）；跨域的授权快照装载留 application，失败归一化调 `authnservice.*`；`LoginRequest` 与 `loginClientMetadata`（传输元数据）留 application。`online_session.go` 吸收 `online_session_usecase.go`（纯 repo 透传，直接合并）。

**provider/wire**：三个模块 `provider.go` 删去全部 `New*Usecase`；`cmd/glex` 的 `wire.Bind`（Transaction×3）不变；`make generate` 重出 `wire_gen.go`；server 注册代码不动（仍收 `*XxxApplication`）。

**测试迁移**：现 usecase 测试直接改为针对合并后的 Application 构造（fake repo/tx/crossdomain 复用，仅构造器签名变化）；`current_user_routes_test.go` 与 `menu_routers_test.go` 的 fake-usecase 接口缝消失，改用已有的 `fakeUserRepo`/`fakeMenuRepo` 驱动真实 Application，DTO 投影断言保留；tx_test、logger_test（component 字符串不变）基本不动。

## 三、文档与契约

- **AGENTS.md**：重画分层图（client → DTO → Application service〔转换 + 跨领域编排：事务/crossdomain/补偿〕→ domain service〔领域内编排〕/ entity ← repository 端口 ← infra）；Application 节删掉 Usecase 条目与 `<Concept>Usecase` 命名规则；Domain 节将"不得机械拆分 entity/repository/service"改为此拆分为**规定**（含根包只放 errors 的规则）；Testing seams、Add-a-resource 清单同步；顺手修复已过时的 `internal/integration` 段落（HEAD 已删除该目录）。
- **新增 ADR 0018**（合并 Usecase 入 Application 服务 + domain 拆 entity/repository/service，supersede 0015，修正 0016 中"Transaction 端口在 Usecase 旁"的表述）；0017 不动。
- **CONTEXT.md** 检查并更新对 Usecase 层的引用。

## 四、执行顺序（每步 `go build ./... && go test ./...` 全绿后提交）

1. `refactor: split the domain modules into entity, repository, and service packages`（含死代码删除、README 重写、全部 import 更新）
2. `refactor: fold the user usecase into the user application service`
3. `refactor: fold the access usecases into the application services`
4. `refactor: fold the authn usecases into the application services`（含 wire 重生成）
5. `docs: adopt the coze-style application and domain layering`（AGENTS.md、ADR 0018、CONTEXT.md）

最终验证：`make all` 确认生成物除 `wire_gen.go` 外无 diff，全量 `go test ./...` 通过。

## 风险与边界

- 纯结构重排、零行为变更；最大的机械风险是 import 批量替换，靠每步全量测试兜底。
- 原强制分层的契约测试（layering_contract_test 等）在 HEAD 已被删除，本 refactor 不恢复；AGENTS.md 文本成为唯一契约载体。
- 三份重复的 `Transaction` 接口与 `fakeTransaction` 测试假件维持各模块一份的现状（跨模块共享违反模块边界约定），不在本次范围内解决。
